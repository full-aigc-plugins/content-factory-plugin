# CF-002 — Host bootstrap and capability probe

Status: IMPLEMENTED_IN_BRANCH

## Scope

Establishes deterministic, no-paid-call host/capability probing plus callable CLI and JSON-RPC handler entry points.

## RED evidence

- Host probe tests introduced in commit `d43c8309622bb4fe9310562820b582a9ec0b1b86`.
- CI initially failed before tests because npm caching required a lockfile; root cause was isolated and the cache flag was removed in commit `02b2580ca8026713b15c90a41ad8b621b275d46e`.
- Entry-point tests were added in commit `d8ee38fd475c8f9bb04888c7f8cd8d0be54ab83e`.
- Test typing was corrected in `b84d3fceec5e478b22f1997a819ad261e2ab0139`.
- Clean RED then failed only because `src/host/probe.ts`, `src/cli.ts`, and `src/mcp.ts` did not exist.

## Contracts

- explicit `CONTENT_FACTORY_HOST` wins over environment inference;
- unknown host remains `unknown`;
- Codex, ZCode, and Kimi can be inferred only from explicit host-specific environment evidence;
- capability inventory is supplied as local JSON and sorted/deduplicated;
- malformed capability inventory produces warnings instead of invented capabilities;
- the probe performs no network request;
- CLI `probe` emits one HostContext JSON document;
- JSON-RPC method `content_factory.probe` returns HostContext;
- unknown JSON-RPC methods return method-not-found rather than invoking unimplemented behavior.

## Deferred

Persistent stdio MCP framing, host-specific deep probes, browser integrations, and actual external-plugin discovery are implemented by later tasks. This task establishes the domain boundary and non-network bootstrap behavior.
