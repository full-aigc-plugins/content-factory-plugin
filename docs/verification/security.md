# 安全与供应链验证

CF-037 把发布前安全检查拆成可重复运行的本地门禁。它验证真实边界行为，不把文件存在、构建成功或 HTTP 成功当作安全证明。

## 覆盖范围

| 边界 | 验证结果 |
|---|---|
| 远程来源 | 每次跳转前重新检查地址；本机、私网和链路本地地址均被阻断 |
| 文档导入 | DOCX 外部关系不解析、不发起网络访问 |
| 内容渲染 | 脚本、危险协议、事件处理属性和 `srcdoc` 被拒绝 |
| 本地导出 | 目标必须位于显式授权根目录内，符号链接不能把写入导向根目录外 |
| 凭据 | 凭据哨兵只传给受控探测端口，不进入返回值、日志或错误细节 |
| 审批 | 仅可信主体、有效时间、明确远程写入授权且绑定当前包与账号的记录可用 |
| 供应链 | 运行时依赖精确固定；外部技能使用不可变标签、提交、目录哈希和许可证据 |

运行发布审计：

```bash
npm run audit:release
```

该命令执行离线供应链完整性检查，并核对运行时依赖、第三方声明、插件许可证与构建门禁。它不访问真实账号，不产生远程写入，也不消耗付费额度。

## 信任边界

本地内核是受支持工作流的门禁，负责校验路径、账号、审批、预算和回执。宿主若允许模型直接调用原生 shell，则 shell 权限仍属于宿主信任边界；本插件不声称能够把宿主提供的系统权限变成绝对沙箱。

当前结果只证明仓库内的离线安全样本和供应链记录通过。真实内容平台、AI 内容检测平台和宿主账号权限未运行时，相关生产验证继续保持 `NOT_RUN`。
