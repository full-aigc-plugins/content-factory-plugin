# 故障恢复验证

CF-038 使用本地故障注入验证恢复纪律。所有网络中断、存储失败和外部写入均为受控模拟，没有耗尽真实磁盘、调用付费接口或修改真实内容平台草稿。

## 恢复矩阵

| 故障 | 预期恢复 | 重复外部写入 |
|---|---|---:|
| 进程在步骤运行中退出 | 识别死亡进程遗留的写锁，保留运行中检查点并恢复同一步 | 0 次自动重放 |
| 对象目录不可写 | 对象写入失败，数据库不登记悬空对象 | 0 |
| 活跃写者持锁 | 第二写者收到可重试的锁定状态 | 0 |
| 草稿写入后响应丢失 | 本地状态记为 `unknown`，重复调用只返回原状态 | 1 次原始写入 |
| 远端人工改稿 | 回读结果记为 `conflict`，要求新审批 | 0 次自动覆盖 |
| AI 内容检测平台断网 | 结果记为 `unknown`，不误报成功 | 1 次受控尝试 |
| AI 内容检测平台响应结构变化 | 保存原始响应，结果记为契约未知 | 0 次盲目重试 |

## 数据库备份

恢复测试通过 SQLite 在线备份接口创建新文件，备份目标存在时拒绝覆盖。测试在备份后继续修改实时数据库，再以只读方式打开备份，确认备份只包含创建时已经提交的数据。备份文件同时返回字节数和 SHA-256，便于后续审计与搬运校验。

## 边界说明

- 死亡进程锁只在操作系统确认 PID 不存在时移出；仍存活或无法确认的进程保持锁定。
- 运行中的远程步骤不会被内核自动标记成功，也不会因恢复而自动重放。
- 本页记录的是故障注入证据，不是生产事故记录。
- 真实账号和付费依赖仍保持 `NOT_RUN`；模拟恢复通过不能替代真实服务故障演练。
